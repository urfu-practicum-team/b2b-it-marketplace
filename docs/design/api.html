B2B-маркетплейс ИТ-услуг с верификацией и эскроу — REST API (1.0.0)

Download OpenAPI specification:Download

API двухсторонней платформы: заказчики (CTO/PM) находят верифицированных ИТ-исполнителей, сделки проходят через эскроу (ЮKassa / Тинькофф, песочница).

Общие соглашения

Жизненный цикл сделки (<code>DealStatus</code>)

Общие соглашения

  • Базовый путь /api/v1, формат JSON (UTF-8), даты — ISO 8601 (UTC).
  • Аутентификация: Authorization: Bearer <accessToken> (JWT, TTL 15 мин). Обновление — /auth/refresh. Refresh-токен — JWT (TTL 7 суток), серверное хранилище токенов не ведётся: выход выполняется удалением токенов на клиенте.
  • Роли: CUSTOMER, EXECUTOR, ADMIN. Ограничения по ролям указаны в описании операций.
  • Деньги — число с двумя знаками после запятой, валюта RUB. Идентификаторы — UUID.
  • Пагинация: ?page=0&size=20&sort=field,desc; ответ содержит items, page, size, totalItems, totalPages.
  • Ошибки — единый формат Error (см. схему). Конфликты состояний — 409 с кодом INVALID_STATE.
  • Операции с деньгами (/deals/{id}/fund) требуют заголовка Idempotency-Key.

Жизненный цикл сделки (DealStatus)

PENDING_FUNDING --(webhook: оплата прошла, деньги удержаны)--> IN_PROGRESS
IN_PROGRESS     --(исполнитель сдал результат)--------------> IN_REVIEW
IN_REVIEW       --(заказчик принял)-------------------------> ACCEPTED --(выплата прошла)--> COMPLETED
IN_REVIEW       --(заказчик запросил доработку)-------------> IN_PROGRESS
IN_PROGRESS|IN_REVIEW --(любая сторона открыла спор)--------> DISPUTED
DISPUTED        --(решение админа)--> COMPLETED (выплата исполнителю) | REFUNDED (возврат заказчику)
PENDING_FUNDING --(отмена любой стороной)-------------------> CANCELLED

Допущения (согласовать с заказчиком проекта)

  • Комиссия платформы удерживается из суммы выплаты исполнителю; заказчик платит ровно amount.
  • Откликаться на заказы могут только исполнители со статусом верификации VERIFIED.
  • Платёжные провайдеры работают в тестовом режиме (песочница); реальные деньги и реальные ПДн не используются.
