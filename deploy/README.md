# Выкладка на стенд

Push в `main` запускает сборку Spring и React. Actions передаёт оба архива по одному SSH-соединению. На VPS `flock` сериализует выкладки. Номер запуска в имени активной конфигурации защищает от запоздавшей сборки более раннего коммита.

## Разовая настройка

1. На VPS установите Docker с Compose 2.24.4+, Bash, Python 3 и `flock`. Скопируйте `compose.yaml`, `db/init-app.sh` и каталог `deploy/` в выбранный администратором каталог, сохранив структуру. При изменении сценария или Compose обновите их на VPS.
2. Подготовьте отдельного пользователя для доставки с доступом к Docker. Предоставьте ему запись в каталог состояния `DEPLOY_ROOT`. По умолчанию скрипт использует `/srv/b2b-it-marketplace/deploy`. Для `MARKETPLACE_SECRETS_DIR` укажите абсолютный путь к действующим секретам БД. Spring запускается с UID 10001 и пишет в общий каталог портфолио. На новом стенде подготовьте пароли и каталог по инструкции локального запуска.
3. Для отдельного ключа Ed25519 добавьте следующую строку в `authorized_keys` пользователя доставки, подставив публичный ключ. Файлы приёмника и настройки SSH должны принадлежать администратору.

   ```text
   restrict,command="env MARKETPLACE_SECRETS_DIR=/path/to/secrets /usr/bin/python3 /path/to/project/deploy/receive.py" ssh-ed25519 <public-key>
   ```

4. В GitHub Environment `stand` разрешите выкладку ветке `main`. Задайте переменные `STAND_SSH_HOST`, `STAND_SSH_PORT`, `STAND_SSH_USER`, секрет `STAND_SSH_KEY` с приватным ключом доставки и `STAND_KNOWN_HOSTS` с проверенным публичным ключом VPS. Для нестандартного порта первая колонка имеет вид `[host]:port`.

## Переключение

При первом переходе со старой схемы скрипт запускает `backend-blue` рядом с действующим Spring. После readiness и проверки новой конфигурации Compose один раз пересоздаёт контейнер `web` для подключения каталогов. На этом шаге возможен короткий перерыв на порту 8081. Последующие выкладки переключают Nginx через reload.

Flyway запускается при старте каждого экземпляра. Добавляйте миграции, совместимые с предыдущей версией Spring, поскольку она продолжает обслуживать пользователей во время обновления. Ошибка readiness оставляет прежнюю версию на трафике. При ошибке `nginx -t` скрипт восстанавливает ссылку. При долгих открытых соединениях оба Spring остаются запущенными до следующей попытки. Повторить выкладку можно через **Re-run jobs** в Actions.

Проверка активного релиза и публичного API на VPS:

```sh
readlink /srv/b2b-it-marketplace/deploy/routes/active.conf
docker ps --filter label=com.docker.compose.project=b2b-it-marketplace
curl -fsS "${STAND_URL:?}/api/v1/health"
```
